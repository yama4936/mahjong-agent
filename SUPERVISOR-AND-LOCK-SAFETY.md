# Operator supervisor and endpoint lock boundaries

The ranked supervisor starts ranked yonma only. It adopts a live operator without interruption, but after an adopted friend-mode or unknown-scope operator exits it records a persistent hold instead of starting a ranked operator. Its saved state includes the adopted scope; older state files without a scope are treated as unknown. A `sanma_friend_stopped` terminal event is also recognized. This safety hold is not a friend-match recovery implementation; resumption still needs evidence of room, match continuity and pending input outcome. The supervisor still holds on intentional or unknown safety stops, does not kill an unresponsive browser, and rate-limits launches.

New operator processes use a per-user, per-CDP-endpoint lock under the Unix account's passwd home `.cache/jantama-auto/locks`, independent of `TMPDIR`, while preserving loopback aliases and separate endpoint ports. They create the parent directory with mode 0700 when missing; the kernel releases the lock when the owner exits. Windows uses the account home path. Different users, containers or filesystem namespaces may not share this directory.

**Migration limitation:** older operators use a lock under their own temporary directory and do not acquire the new lock. A new process cannot safely assume the new lock excludes an already-running old process. Apply or restart only after the current match is known to have ended and process inspection confirms no old operator is running. Do not start old and new versions concurrently. The supervisor process scan provides another check but cannot make mixed-version locks atomic.

The supervisor itself is not a sanma ranked implementation and is not automatically started by `run-operator.mjs`. The code does not solve browser/game rendering failure or prove that a rank room is available. Stop and recovery events should be examined alongside the per-run logs and evidence; the persistent hold must not be silently cleared.

Endpoint ownership tests start separate real processes with different `TMPDIR`, `HOME` and `XDG_CACHE_HOME` values: the same loopback endpoint is rejected, a different port is allowed, and a killed owner releases its lock. If the account home cannot provide the lock directory, acquisition raises an error instead of continuing unlocked. The process scanner only adopts an operator or launcher whose CDP endpoint matches, even within the same checkout. An adopted launcher that disappears before its child becomes visible is also tracked by scope, so a failed friend launcher cannot turn into ranked recovery.

# 対局記録サイト

段位戦・友人戦を分け、1対局ごとの最終結果画像と局結果画像を閲覧する静的サイトです。

## 更新

リポジトリのルートで `node web/results/export.mjs .` を実行します。既存の sharp 依存を使用します。生成先は `web/results/dist/`（Git対象外）。`python3 -m http.server 8766 --directory web/results/dist` でローカル表示できます。

公開先の Site ID は `.openai/hosting.json` に保存されています。Sites の既存サイト更新手順で、このディレクトリと生成済み dist を独立した Sites チェックアウトへ同期・パッケージ化・現在の公開範囲を維持してデプロイしてください。この手順は画面・機能の変更と障害時の保存済みデータ更新に使用します。対局データの日常更新は `../../deploy/results/README.md` の自動配信経路を使用します。

## データの範囲

- artifacts 以下の python-operator.jsonl の outcome_observed / match を対局終了記録として採用。
- 同一の結果画像は SHA-256 で重複除外。同じ実行内の60秒未満の再検出も除外。
- matches/*.json と ranked-match-results.jsonl の確定結果を画像ファイル名で照合。
- 2026-10-26 JSTの8件は、2026-10-27に実際に閲覧した最終結果画像から順位と点数を補完。
- 最終結果が記録されていない実行はデータ出力・一覧・件数・CSVから除外します。元の運用ログは保持します。
- 対局数は終了確認済みの件数です。順位未確認を順位統計に含めません。対局途中の点数から最終順位を推測しません。
- 友人戦と段位戦の統計は分離。全記録タブで混合勝率は出しません。
- 時間設定は実行名由来、操作期限は記録値です。前者が実際の設定画面で独立確認されたことを意味しません。
- 結果画像を WebP に変換して同梱します。元ログ全体、認証情報、ブラウザプロファイルは配信しません。
- 各局画像はその実行ログ内で最終結果までに観測した順序です。再起動前の局が欠ける場合があります。
- 対局PCのタイマーが約1分間隔で公開記録を再生成し、一覧・役の分析・グラフは30秒ごとに取得します。新しい対局ごとのSites再公開は不要です。

`node --check web/results/export.mjs`

`node --check web/results/src/app.js`

`node web/results/verify.mjs` （生成後）

## 自分の和了・役表示

操作者が自分のロン／ツモ操作を確認した後、0.5秒間隔・最大15秒（30枚）のPNG連続画像を保存します。Canvasの役表示アニメーションは `animations="disabled"` だけでは止まらないため、出始めの1枚だけを採用しません。撮影中は結果確認ボタンを押さず、次の局の卓が確認できた場合や最終結果に達した場合は早期終了します。役名のOCR判定は行いません。

`self_win_frame` の画像は、同じ実行ログで後続の対局終了が確認された場合だけ `selfWins` に取り込みます。サイトの「自分の和了・役表示」で時系列に閲覧・拡大できます。途中終了した対局は掲載しません。追加前の対局や手動和了、操作者を再起動した区間を跨ぐ紐付けは対象外です。

操作者の再起動後に記録が有効になります。生成済みの対局記録は自動更新経路で反映されます。

検証: `node --test web/results/export.test.mjs`、`python -m unittest discover -s python -p test_self_win_capture.py`。実対局の確認は友人戦300+0、操作期限300000msで行います。

## 過去の役の分析

`analysis.html` に自分の和了操作の履歴・役の確認件数・CSV保存を追加しています。`reaction_win` / `decision` のクリック済みロン・ツモと、その後最初の局結果画像を関連付け、対局終了が確認できた区間だけ採用します。操作種別は実際の和了方式の画像確認とは区別してください。

`yaku-reviewed.json` は2026-10-27に過去189枚を目視確認した記録です。画像SHA-256と和了IDの両方が一致した場合だけ適用します。16枚で一部の役名が読め、173枚は役表示前・途中のため未確認です。役候補・手牌・戦略ログから役を推測していません。画像表示途中のため、全件が不完全な観測です。確認件数は下限であり、役の出現率や平均打点は算出しません。点数不明はnullです。表示された1翻30符も最終確定値とは扱いません。裏ドラ0翻の表示は保持しますが、ドラの確認件数には加えません。

新しい履歴は未レビューとして追加されます。CSVは絞り込み後の1和了1行で、役・ドラ・確認状況・画像URL・原画像ハッシュを含みます。空欄は未確認を示し、0ではありません。

## グラフ分析

`charts.html` で対局種別とJSTの日付範囲を指定できます。順位分布、順位が10戦連続で判明した区間の移動平均、日別終了対局数、画像で確認できた役の最低件数を表示します。欠損順位は線を切り、未観測日をゼロ補間しません。役の欠損を役なしとみなさず、確認状況と母数を併記します。各グラフには数値表があり、平均順位の表から対局へ移動できます。

設計には事前に検索・取得したOpenAIの[d3-data-visualizationスキル](https://github.com/openai/plugins/blob/main/plugins/build-web-data-visualization/skills/d3-data-visualization/SKILL.md)を使用。D3 7.9.0をライセンスとともに同梱し、外部CDNへの実行時依存を避けています。

技術設計: 同時に4つのSVGを描画します。D3はスケール・軸・形状を担当し、集計モデルはchart-data.mjsに分離。データ量が小さいためCanvasよりも数値表と対応付けやすいSVGを採用。画面幅の変化で寸法・目盛数を再計算し、モバイルでは1列表示。主要操作は44px以上のネイティブコントロール、値は常時ラベル/数値表で確認でき、ホバーやドラッグに依存しません。スクロール・ピンチ操作を奪わず、動きの演出は使いません。大規模化した場合は日別集約や表示期間の制限を優先します。

検証: `node --test web/results/chart-data.test.mjs web/results/export.test.mjs`。欠損区間・カテゴリ分離・日付境界・未完了除外・役とドラの分離を確認します。

## 仕組みと記録の読み方

`how-it-works.html` は画面認識、ローカル判断とJev、操作モード、結果抽出、統計の分母、役の確認範囲、検証条件を説明します。一覧・役の分析・グラフ分析から移動できます。実装を変えた際は説明も見直し、過去の対局に現行設定を一律に適用しないでください。公開範囲は一般公開です。

## ライブ観戦

`live.html` にプレイヤーを直接表示し、DockerのWebSocket配信を受信します。外部ページをiframeで埋め込まないため、プレイヤー内の移動で対局一覧が入れ子になることはありません。ライブ配信はアーカイブ更新とは独立しています。構成・起動・停止・検証方法は `../../deploy/live/README.md` を参照。公開元は `https://jantama-live.yama.asia/` です。

## ナビゲーション

全5ページを共通サイドバーで移動できます。現在のページは `aria-current` で表示し、800px以下では開閉メニューになります。Escapeで閉じてボタンへフォーカスを戻します。`shell.css` / `shell.js` が共通の見た目と開閉を担当します。`live-view.js` は独立プレイヤーの `web/live/live.js` と同じ受信処理です。配信プロトコル変更時は両方を更新してください。

# 分析用の自動記録

操作者の次回起動から、実行ディレクトリの `analysis/<matchId>/` に終了確認済みの対局を保存します。途中終了のデータは分析用に確定しません。内部の `.pending.jsonl` は作業用であり、集計対象外です。操作者を再起動した場合、再起動前の未完区間との自動結合は行いません。元の python-operator.jsonl は従来どおり保持します。

- `events.jsonl`: schemaVersion=1。対局ID・実行名・日時・局区間番号と、観測状態・評価・操作・結果画像を保持。
- `decisions.csv`: 1判断/操作1行。表計算やPythonで分析できる形式。配列・辞書はJSON文字列。

記録対象は、手牌、ツモ牌、河、副露、ドラ表示牌、点棒、場風/自風、本場/供託、巡目、残り牌、相手の観測状態、立直状態、候補手、選択手、評価値、安全度、方針、認識確信度、キャッシュ情報、処理時間、操作成否、和了結果の連続画像への参照です。詳細フィールドは元の評価器が返した内容をそのまま保持します。観測できなかった値は欠損のままです。

認識状態と戦略評価は推定です。候補の役・期待打点を実際の和了役・実打点として扱わないでください。結果画面の存在だけで放銃者・和了点・収支を推定しません。`confirmedResult` は現在nullで、確定結果の解析は別工程です。画像の役の目視確認はweb/results/yaku-reviewed.jsonで管理します。局区間番号はログ内の局結果観測順であり、公式の局IDではありません。

段位戦と友人戦はrunに基づいて分けて分析してください。時間設定が確認できない記録は不明としてください。300+0の機能試験を短時間設定での強さの評価に混ぜないでください。

## 過去ログの変換

リポジトリルートから:

```sh
python3 python/analysis_recorder.py --root . --output artifacts/analysis
```

実行名のハッシュごとに保存します。同一の最終画像パスから対局IDを生成するためサイトの対局IDとも照合できます。再実行時は既存の完了ファイルを保持し、同じ結果の再検出で判断記録を上書きしません。不正JSON行は件数を報告してスキップします。終了未確認の作業ファイルは変換終了時に削除します。

これはローカル分析データです。大容量の手牌・候補手全履歴をサイトへ自動配信はしません。サイトは従来どおり再生成・公開時のスナップショットです。保存エラーはstderrへ通知し、対局操作と元ログの保存は継続します。

検証: `python -m unittest discover -s python -p test_analysis_recorder.py`。完了前の除外、結果の重複、CSVへの情報保持、欠損値を検証します。実対局テストはこの変更では実施していません。
